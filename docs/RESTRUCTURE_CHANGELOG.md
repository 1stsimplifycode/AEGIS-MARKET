## Defects found and fixed during this phase

1. **`shift` in `tools/aegis_module.bat` renumbered `%0`.** A bare `shift` in Windows
   batch shifts the script's own name as well as its arguments, so reading `%~dp0`
   afterwards resolved against the module id instead of the script and put the repository
   root one directory too high. Symptom: `research_modules.yaml not found under
   C:\Users\abcom\Downloads`. Fixed by resolving the root before any shift and using
   `shift /1`. Found by running the module, not by reading the file.

2. **`MULTIMODAL-13` called `demonstrate_degeneracy()` with no arguments.** The canonical
   function takes five. The adapter now builds its inputs exactly as
   `tests/property/test_regime_degeneracy.py` does, including the deliberately large
   regime terms, and reproduces a maximum absolute weight difference of 2.887e-15.

3. **`MULTIMODAL-11` omitted `block_columns`.** `asynchrony_sensitivity` requires the
   column list to shift. Fixed by passing the modality's own block columns from
   `MODALITY_BLOCKS`. The corrected run reproduces AUPRC 0.9412 at offset 0, identical to
   the FULL arm.

4. **`STATS-16` was marked `INFRASTRUCTURE_ONLY` while naming canonical code.** Caught by
   the validator's own consistency rule. The listed statistics functions exist but the
   adapter does not call them — they are what the missing multi-seed driver *will*
   consume. Moved to a separate `will_consume:` field rather than weakening the rule.

All four were defects in new code written during this phase. None was a regression in
existing behaviour.
